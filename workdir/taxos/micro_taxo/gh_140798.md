# Micro Taxonomy: CPython #140798

## Metadata
- Issue: https://github.com/python/cpython/issues/140798
- Component: `threading.local`; tracing
- Bug class: memory leak
- Detection: LeakSanitizer

## Root Cause
The report enables a trace callback that reads frame code and records events
while threads interact with thread-local state. Two 24-byte direct allocations
survive shutdown, indicating thread-local or tracing bookkeeping not released
on a traced-thread cleanup path.

## Trigger
1. Install a trace function that records each event.
2. Execute the supplied threading and thread-local workload.
3. Allow threads to complete and exit.
4. LeakSanitizer reports two direct 24-byte leaks.

## Reproducer

```python
import threading

events = []

def tracer(frame, event, arg):
    try:
        func_name = frame.f_code.co_name
    except Exception:
        func_name = 1.7976931348623157e308
    events.append((threading.current_thread().name, event, func_name))
    return tracer

def callback():
    for _ in range(3):
        try:
            next(callback.g)
        except StopIteration:
            break

callback.g = iter(range(3))

old_threading_trace = getattr(threading, "_trace_hook", Ellipsis)
try:
    threading.settrace(tracer)
    t = threading.Thread(target=callback, name="child-thread")
    t.start()
    t.join()
finally:
    threading.settrace(old_threading_trace)
```


## Relevant State
- Per-thread state: `threading.local`
- Instrumentation: trace function and event list
- Leak total: 48 bytes in two allocations

## Leak Path
Thread-local teardown and trace-state teardown interact; one or both retain
small per-thread allocations after the thread has finished.

## Fix
Audit traced-thread destruction for thread-local and trace-object references;
release each per-thread allocation after final trace callbacks complete.
