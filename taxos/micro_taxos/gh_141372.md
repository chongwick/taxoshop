# Micro Taxonomy: CPython #141372

## Metadata
- Issue: https://github.com/python/cpython/issues/141372
- Component: `cProfile.Profile`; monitoring integration
- Bug class: memory leak
- Detection: LeakSanitizer

## Root Cause
Replacing `sys.monitoring` with a minimal stub before constructing
`cProfile.Profile` leaves a 40-byte allocation unreleased. The report
indicates an initialization failure or fallback path that does not release a
partially created profiler resource.

## Trigger
1. Replace `sys.monitoring` with an object exposing only `MISSING`.
2. Construct `cProfile.Profile`.
3. Exit the process.
4. LeakSanitizer reports a 40-byte direct leak.

## Reproducer

```python
import cProfile
import sys

class _MonitoringStub:
    MISSING = object()

sys.monitoring = _MonitoringStub()

prof = cProfile.Profile()
```


## Relevant State
- Owner: `ProfilerObject`
- Boundary: monitoring API setup
- Exceptional state: incomplete monitoring implementation

## Leak Path
Profiler initialization allocates state before relying on monitoring methods
that the stub does not implement; cleanup is not completed on that path.

## Fix
Make monitoring setup transactional: validate the required monitoring API
before allocation, or release all allocated profiler state on setup failure.
