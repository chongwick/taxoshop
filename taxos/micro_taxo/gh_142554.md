### What happened?

Missing length check on the return value of `_pylong.int_divmod` method leads to out-of-bound read.

**Proof of Concept:**
```python
import _pylong

_pylong.int_divmod = lambda a, b: (123,)  # wrong shape

huge  = 10**8000
small = 10**4000
divmod(huge, small)
```

pylong_int_divmod(PyLongObject *v, PyLongObject *w,
                  PyLongObject **pdiv, PyLongObject **pmod)
{
    PyObject *mod = PyImport_ImportModule("_pylong");
    if (mod == NULL) {
        return -1;
    }
    PyObject *result = PyObject_CallMethod(mod, "int_divmod", "OO", v, w);
    Py_DECREF(mod);
    if (result == NULL) {
        return -1;
    }
    if (!PyTuple_Check(result)) { // Bug: Only Check the type, but not the shape.
        Py_DECREF(result);
        PyErr_SetString(PyExc_ValueError,
                        "tuple is required from int_divmod()");
        return -1;
    }
    PyObject *q = PyTuple_GET_ITEM(result, 0);
    PyObject *r = PyTuple_GET_ITEM(result, 1);
    if (!PyLong_Check(q) || !PyLong_Check(r)) {
        Py_DECREF(result);
        PyErr_SetString(PyExc_ValueError,
                        "tuple of int is required from int_divmod()");
        return -1;
    }
    if (pdiv != NULL) {
        *pdiv = (PyLongObject *)Py_NewRef(q);
    }

Hi @skirpichev, thank you for your prompt response!

I originally believed that we should check not only the type but also the *shape* (length) of the returned value before using any type casting and length-based operation. It doesn’t hurt to add a length check in addition to the type check, and it helps avoid a hard crash of the program.

```
    PyObject *result = PyObject_CallMethod(mod, "int_divmod", "OO", v, w);

    if (!PyTuple_Check(result)) { // Bug: Only Check the type, but not the shape.
        Py_DECREF(result);
        PyErr_SetString(PyExc_ValueError,
                        "tuple is required from int_divmod()");
        return -1;
    }
    PyObject *q = PyTuple_GET_ITEM(result, 0);
    PyObject *r = PyTuple_GET_ITEM(result, 1);
```

However, I’m not very familiar with CPython’s preferences on what should be treated as a bug versus what is considered acceptable behavior, even if it may cause a crash. I’d be happy to follow the project’s conventions here.
