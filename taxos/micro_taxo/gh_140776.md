Source: [https://github.com/python/cpython/issues/140776#issuecomment-3468698082](https://github.com/python/cpython/issues/140776#issuecomment-3468698082)

```text
I'm not really sure we should consider messing with `co_*` fields as legitimate. We do have some checks here and there, but I think we shouldn't do much. It's known that putting garbage in `co_consts` will lead to errors as it'd no more relevant to the rest of the code object.

There is an open issue about it: https://github.com/python/cpython/issues/122850 which planned to disallow arbitrary objects but it wouldn't help in this case I think.

cc @encukou 
```

```text
This has nothing to do with the `textwrap` module. You messed with the bytecode object, you break some invariants, you get an undefined behavior. The bug is not in Python, but in the user code.

There are many other ways to trigger a crash by messing with the code object.  Correctness of the bytecode cannot be checked in principle, and correctness of other code object attributes is not checked (apart from a superficial check) for performance reasons.
```
