````text
# Bug report

### Bug description:

When python is built with memory sanitizer enabled, reading any data returned by `os.getrandom()` will trigger a memory sanitizer false positive, because the buffer is filled using a syscall, and the memory isn't marked as having been written to.

Currently, 
```
$ cat test.py 
import os
data = os.getrandom(32)
h = data.hex()
print(f'h={h}')

$ ./python ./test.py 
Uninitialized bytes in memchr at offset 18 inside [0x707000006458, 66)
==242471==WARNING: MemorySanitizer: use-of-uninitialized-value
...
SUMMARY: MemorySanitizer: use-of-uninitialized-value /home/peter/dev/pvanvugt-cpython/Objects/stringlib/fastsearch.h:58:13 in ucs1lib_find_char
Exiting
```

I have verified that applying `__masan_unpoison()` to the data fixes this.

### CPython versions tested on:

CPython main branch

### Operating systems tested on:

Linux
````

### Comment 2 — encukou, 2026-04-22T09:30:43Z

Source: [https://github.com/python/cpython/issues/148850#issuecomment-4295099411](https://github.com/python/cpython/issues/148850#issuecomment-4295099411)

```text
Yes, `__msan_unpoison` is available on any platform with (clang-style) MSAN support. That's not all PEP-11 platforms, but that's OK.

We already use `__msan_unpoison` in a bunch of places.

See also #11375. 2018 was a different time though :)
I'd prefer adding a wrapper macro to `pyport.h`, in the spirit of `_Py_MEMORY_SANITIZER` or `_Py_NO_SANITIZE_THREAD`: e.g. `_Py_MSAN_UNPOISON(p, sz)` should call `__msan_unpoison` if it's available, and do nothing otherwise.
```
