```text
I think returning `hash` like @kumaraditya303 suggests makes sense here.

> My understanding for using the get_ob_shash(a) is that the getter ensures ob_shash isn't changed while it is being read.

Not exactly. Atomics loads with `memory_order_relaxed` that we use here basically achieve two things:

1) The load is atomic (i.e., a single indivisible operation). In particular, the compiler is not going to load parts of the field separately and then combine it. (In practice, that would be unlikely to happen anyways.)
2) The main thing is that it avoids undefined behavior. The language declares that data races, such as concurrent reads and writes, are undefined behavior. However, concurrent reads and writes that use atomics are not undefined behavior. So that means that thread sanitizer won't issue warnings here.
```

I personally use docker containers to build cpython with clang+TSAN+free-threading, here is how you can install everything and build cpython inside a docker container:
```bash
cd cpython
docker run -it \
    -v $PWD:/cpython \
    -w /cpython \
    --name=cpython-dev-nogil-tsan \
    --cap-add=SYS_ADMIN \
    --cap-add=SYS_PTRACE \
    --network=host --security-opt seccomp:unconfined --ipc=host \
    ubuntu@sha256:b359f1067efa76f37863778f7b6d0e8d911e3ee8efa807ad01fbf5dc1ef9006b \
    /bin/bash

# Inside the docker container:
apt-get update && ln -fs /usr/share/zoneinfo/Europe/Paris /etc/localtime && \
    apt-get install -y tzdata && \
    dpkg-reconfigure --frontend noninteractive tzdata
    apt-get install -y git wget cmake --no-install-recommends && \
    apt install -y ccache clang-18 libstdc++-14-dev build-essential libssl-dev \
            zlib1g-dev libbz2-dev libreadline-dev libsqlite3-dev curl git \
            libncursesw5-dev xz-utils tk-dev libxml2-dev libxmlsec1-dev \
            libffi-dev liblzma-dev

    cd /cpython && \
    CC=clang-18 CXX=clang++-18 ./configure --disable-gil --with-thread-sanitizer --prefix $PWD/output-python && \
    make -j 8 && \
    make install && \
    export PATH=$PWD/output-python/bin:$PATH && \
    python3.13t -VV && \
    python3.13t -m pip --version && \
    PYTHON_GIL=0 python3.13t -c "import sys; print(sys._is_gil_enabled())"
```
The drawback of the approach maybe if you are not comfortable with gdb for debugging and using terminal to execute any command.
