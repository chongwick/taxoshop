# Micro Taxonomy: CPython #141044

## Metadata
- Issue: https://github.com/python/cpython/issues/141044
- Component: thread stack-size configuration
- Bug class: memory leak
- Detection: LeakSanitizer

## Root Cause
Changing the requested thread stack size, starting a thread, and resetting the
size leaves six allocations totaling 544 bytes. The report indicates that
stack-size configuration or thread startup retains bookkeeping after the
worker has joined.

## Trigger
1. Set a non-default stack size.
2. Start and join a worker thread.
3. Reset the stack size to zero.
4. Exit and observe LeakSanitizer allocations.

## Relevant State
- Global setting: `threading.stack_size()`
- Lifecycle: configured -> worker start/join -> reset
- Leak total: 544 bytes in six allocations

## Leak Path
Thread-start or stack-configuration state survives both thread completion and
configuration reset.

## Fix
Associate stack-size bookkeeping with the thread or configuration lifetime and
release it after join or when the default configuration is restored.

## Pattern Tags
- threading
- global-configuration
- lifecycle-cleanup
