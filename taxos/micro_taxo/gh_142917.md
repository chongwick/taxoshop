# Micro Taxonomy: CPython #142917

## Metadata
- Issue: https://github.com/python/cpython/issues/142917
- Component: recursion handling / `collections.UserList`
- Bug class: memory leak
- Detection: LeakSanitizer, with an unavailable external symbolizer

## Root Cause
The report establishes a 1,320-byte leak after recursive comparisons of
cyclic `UserList` instances, but the unsymbolized allocation trace does not
identify the allocating CPython function. The issue title's symbolizer warning
is diagnostic noise, not the reported leak's root cause.

## Trigger
1. Build two `UserList` objects that contain one another.
2. Run recursive equality and ordering comparisons under an infinite-recursion
   test guard.
3. Exit after each comparison raises `RecursionError`.
4. LeakSanitizer reports one unreleased allocation.

## Relevant State
- Objects: cyclic `UserList` pair
- Boundary: recursion-error unwinding
- Evidence quality: allocation stack is not symbolized

## Leak Path
The allocation survives process exit after recursive rich-comparison error
handling. A precise owner cannot be assigned from the report alone.

## Fix
Reproduce with a usable symbolizer, identify the allocation retained across
recursion unwinding, and balance cleanup on every comparison error path.
