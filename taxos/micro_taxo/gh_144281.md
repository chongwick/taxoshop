# Micro Taxonomy: CPython #144281

## Metadata
- Issue: https://github.com/python/cpython/issues/144281
- Component: `Objects/memoryobject.c`; `multiprocessing.shared_memory`
- Bug class: invalid write / SIGBUS
- Detection: AddressSanitizer

## Root Cause
The report demonstrates a write through a shared-memory-backed `memoryview`,
but does not establish why the mapped destination becomes invalid. ASan reports
the fault in `memmove`, reached from `copy_base()` and `memory_ass_sub()`.

## Trigger
1. Create a ten-byte `SharedMemory` segment.
2. Assign five bytes through `shm.buf[:5]`.
3. ASan reports a BUS signal during the buffer copy.

## Reproducer

```python
from multiprocessing import shared_memory

# Create shared memory
shm = shared_memory.SharedMemory(create=True, size=10)

# Potential trigger: Accessing the buffer while the underlying 
# resource is being manipulated or in a specific state.
try:
    shm.buf[:5] = b'hello'
finally:
    shm.close()
    shm.unlink()
```


## Relevant State
- Exporter: `SharedMemory`
- View: `shm.buf`
- Write path: `memory_ass_sub()` -> `copy_single()` -> `copy_base()`

## Failure Site
- `Objects/memoryobject.c:353` `copy_base()`
- `Objects/memoryobject.c:2720` `memory_ass_sub()`

## Fix
Confirm the shared-memory mapping and buffer-export lifetime before copying;
reject or remap an invalid destination rather than passing it to `memmove`.
