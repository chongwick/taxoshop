For me it's 56 bytes rather than 32 but it's the same code location — the code at `xmlparse.c:6096` is this:

https://github.com/python/cpython/blob/d74a96366df58b6e55d4a03612c3e67da2211ddd/Modules/expat/xmlparse.c#L6096

libexpat allocates the content model there and it must be freed by a call to [`XML_FreeContentModel`](https://libexpat.github.io/doc/api/latest/#XML_FreeContentModel) by the element declaration handler when one is registered as with our case. The CPython code at…

https://github.com/python/cpython/blob/d74a96366df58b6e55d4a03612c3e67da2211ddd/Modules/pyexpat.c#L675-L678

…in function `my_ElementDeclHandler` does that — good! —, but there is one exit path in the function that bypasses this clean-up, here:

https://github.com/python/cpython/blob/d74a96366df58b6e55d4a03612c3e67da2211ddd/Modules/pyexpat.c#L644-L645

Once I turn that `return` into `goto finally;` the leak disappears. Pull request #140602 fixes that issue and is ready for review :beers:
