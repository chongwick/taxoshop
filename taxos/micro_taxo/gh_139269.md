#### Description

```text
This PR fixes a series of misaligned memory access errors in the JIT engine that were causing segmentation faults when running tests with AddressSanitizer (ASan) and UndefinedBehaviorSanitizer (UBSan) enabled.

The unsafe direct pointer casts in `patch_32`, `patch_32r`, `patch_64`, and `patch_x86_64_32rx` have been replaced with `memcpy` to ensure safe, alignment-agnostic memory operations.
```

```text
No, should not cast to `uint64_t*`. Using `void*` is the correct and safer approach.

Casting to `uint64_t*` can cause undefined behavior due to:
1.  **Strict Aliasing Rule:** Accessing an object through a pointer of an incompatible type can lead to incorrect optimizations by the compiler.
2.  **Alignment Issues:** If the source address (`value + 4`) is not aligned for a `uint64_t`, creating a `uint64_t*` can cause a crash or performance degradation on some CPU architectures.

The `memcpy` function is designed to work with `void*` to safely copy raw bytes, avoiding these issues.
```
