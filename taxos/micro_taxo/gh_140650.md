```text
What's the use case you have where `self.closed` does not exist? `BufferedReader` expects its `raw` to be a `RawIOBase`; `RawIOBase` inherits from `IOBase` which provides a closed attribute (https://docs.python.org/3/library/io.html#io.IOBase.closed).

I'm 👍on fixing the crash (_io__Buffered_close_impl should return NULL if there is an active exception). Given `IS_CLOSED` is used in some other macros (ex. CHECK_CLOSED) I'm a little worried about touching it. I think the `-1` result from `buffered_closed` gets coerced to a bool by C rules / `1` so we end up in the `if (r > 0)` case. Inside that removing the `-1` case and only setting res to None if https://docs.python.org/3/c-api/exceptions.html#c.PyErr_Occurred is false I think would be a fairly tactical fix.
```

I want to make sure disambiguating crash: "The interpreter exits with an exception / error message" is distinct from "There's a segfault".
