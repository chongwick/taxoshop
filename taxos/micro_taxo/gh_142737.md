````text
Full message (please include it when possible):

```
Exception ignored in the internal traceback machinery:
AttributeError: 'object' object has no attribute '_print_exception_bltin'
Traceback (most recent call last):
  File "/home/bswck/Python/cpython/t.py", line 12, in <module>
python: Objects/call.c:618: callmethod: Assertion `callable != NULL' failed.
Fatal Python error: Aborted
Aborted (core dumped)
```

The problem happens because `_Py_FindSourceFile` resorts to `_PyObject_CallMethodFormat` which assumes `callable` is healthy (the `callable` in this case is the result of getting `open` of `io`, which is `NULL` because `io` is an `object()` from `test_import`).
Maybe NULL-check the `callable` first? (PR in progress)
````

### Comment 2 — ZeroIntensity, 2025-12-15T13:58:23Z

Source: [https://github.com/python/cpython/issues/142737#issuecomment-3655786308](https://github.com/python/cpython/issues/142737#issuecomment-3655786308)

```text
> Maybe NULL-check the callable first? (PR in progress)

I think the issue is here:

https://github.com/python/cpython/blob/14d3974db01b6c4b14a4829b4310b2511993aa8e/Python/traceback.c#L417-L420

We need to check for a `NULL` result from `PyObject_GetAttr`, not defer the check to `_PyObject_CallMethodFormat`, because:

1. That will slow things down for other callers.
2. It's generally unsafe to call arbitrary C API functions with an exception set.
```
