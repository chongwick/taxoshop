#### Description

```text
## Summary
- Fix assertion failure in `io.TextIOWrapper.tell()` when reading files ending with standalone `\r`
- Add comprehensive test case to prevent regression
- Add NEWS entry documenting the fix

## Root Cause
The tell() optimization algorithm assumed buffered data would always be available when calculating position, but files ending with standalone `\r` create empty snapshots, causing `assert(skip_back <= PyBytes_GET_SIZE(next_input))` to fail.

## Fix
Added check to skip optimization when `next_input` is empty, preventing the assertion failure while maintaining correct position calculation.

## Test Plan
- [x] Added test case `test_tell_after_readline_with_cr` in `test_textio.py`
- [x] Verified fix handles standalone carriage returns correctly
```

```text
@StanFromIreland , Thanks, I reproduced this issue, and I think the assertion failure occurs because the tell() method's optimization algorithm assumes there's buffered input data to search through, but when a file ends with a standalone carriage return (\r), an empty snapshot buffer gets created. The algorithm calculates that it needs to skip some bytes based on the character-to-byte ratio, then tries to navigate within the buffer using a binary search approach, but fails when skip_back=1 exceeds the buffer size of 0. I think the cleanest fix is to detect when next_input is empty and skip the optimization phase entirely, letting the algorithm fall back to the precise byte-by-byte decoding method, which always works correctly. I can open the PR if this seems correct.
```
