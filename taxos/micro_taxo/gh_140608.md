# Micro Taxonomy: CPython #140608

## Metadata
- Issue: https://github.com/python/cpython/issues/140608
- Component: `_ssl`; concurrent SSL handshake
- Bug class: double-free
- Detection: AddressSanitizer

## Root Cause
Concurrent SSL handshake activity frees the same OpenSSL allocation from two
threads. ASan's allocating, first-free, and second-free stacks all pass
through `_ssl__SSLSocket_do_handshake_impl()`, indicating unsynchronized
ownership of handshake state shared by the test's SSL connections.

## Trigger
1. Start the supplied SSL POP3 test server and client workload.
2. Run concurrent handshake operations.
3. One thread frees an OpenSSL allocation.
4. Another handshake thread frees the same allocation.

## Relevant State
- Owner: OpenSSL handshake allocation
- Boundary: `_ssl__SSLSocket_do_handshake_impl()`
- Concurrency: two handshake threads

## Invalidating Operation
- First `free()` in an OpenSSL call reached from the SSL handshake

## Stale Use
- Second `free()` in another handshake thread

## Fix
Serialize access to shared SSL handshake state or ensure every handshake owns
an independent OpenSSL object whose teardown occurs exactly once.
