### Original Issue

Source: [https://github.com/python/cpython/issues/142829](https://github.com/python/cpython/issues/142829)

````text
### What happened?

Re-entrant `ContextVar.set` during `_PyHamt_Eq` lets `Context.__eq__` replace a context while `hamt_iterator_next` still walks the old HAMT nodes, leaving the iterator with freed storage and producing a use-after-free when comparing two `Context` instances.

**Proof of Concept:**
```python
import contextvars

var = contextvars.ContextVar("v")
ctx1 = contextvars.Context()
ctx2 = contextvars.Context()


class Boom:
    def __eq__(self, other):
        ctx1.run(lambda: var.set(object()))
        return True


ctx1.run(var.set, Boom())
ctx2.run(var.set, object())
ctx1 == ctx2
```

int
_PyHamt_Eq(PyHamtObject *v, PyHamtObject *w)
{
    if (v == w) {
        return 1;
    }

    if (v->h_count != w->h_count) {
        return 0;
    }

    PyHamtIteratorState iter;
    hamt_iter_t iter_res;
    hamt_find_t find_res;
    PyObject *v_key;
    PyObject *v_val;
    PyObject *w_val;

    hamt_iterator_init(&iter, v->h_root);

    do {
        iter_res = hamt_iterator_next(&iter, &v_key, &v_val);
        if (iter_res == I_ITEM) {
            find_res = hamt_find(w, v_key, &w_val);
            switch (find_res) {
                case F_ERROR:
                    return -1;

                case F_NOT_FOUND:
                    return 0;

                case F_FOUND: {
                    // Bug: Enter the __eq__ method which can tear down the HAMT we’re iterating
                    int cmp = PyObject_RichCompareBool(v_val, w_val, Py_EQ);
                    if (cmp < 0) {
                        return -1;
                    }
                    if (cmp == 0) {
                        return 0;
                    }
                }
            }
        }
    } while (iter_res != I_END);

    return 1;
}
````
