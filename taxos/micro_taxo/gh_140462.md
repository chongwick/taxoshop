````text
> The issue appears to be in the third-party library, I presume we don't sanitise the input (`2147483647`), and it is causing an overflow?

You're absolutely right! It can be reproduced in pure C:

```
$ cat tcurse.c
#include <curses.h>

int main(void) {
    WINDOW * window = initscr();
    subwin(window, 10, 15, 2147483647, 5);
}

$ gcc  tcurse.c  -lncursesw  -o tcurse && ./tcurse
'./tcurse' terminated by signal SIGSEGV (Address boundary error)
```

The ncurses doc tells:

> •   subwin returns ERR if orig is a null pointer, or if any of the ordinate or dimension arguments is negative, or if the resulting window does not fit inside the parent window.


It think this should be reported to ncurses and closed here.
````

```text
So, after looking at the code, I think it'd be too much work for validating this input on our side. It's better that this is validate in ncurses. The rationale is that some functions may or may not require memory allocation, or some functions may require allocation depending on the values. For instance, I don't know why `2147483647` doesn't work. It's `2^31 - 1` which fits on an `int` so there is no overflow here. Maybe that value is then used internally for something else, which then causes an overflow.
```
