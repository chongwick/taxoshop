# Micro Taxonomy: CPython #141542

## Metadata
- Issue: https://github.com/python/cpython/issues/141542
- Component: JIT tracing initialization
- Bug class: memory leak
- Detection: LeakSanitizer

## Root Cause
The report shows a 72,000-byte direct allocation surviving a workload that
exercises JIT tracing initialization. It attributes the leak to
`_PyJit_TryInitializeTracing`, but the supplied report does not isolate the
exact ownership transition that is missed.

## Trigger
1. Run the supplied threaded CPU-idle/CPU-active unittest workload.
2. Cause the JIT tracing path to initialize.
3. Finish the workload and exit.
4. LeakSanitizer reports the retained direct allocation.

## Reproducer

```python
import threading
import time
import unittest
class TestCpuModeFiltering(unittest.TestCase):
        def idle_worker():
            try:
                time.sleep(5)
            except Exception:
                return
        def cpu_active_worker():
            end = time.time() + 0.1
            x = 0
            while time.time() < end:
                x += 1
        cpu_thread = threading.Thread(target=cpu_active_worker, name="cpu_active_worker", daemon=True)
        cpu_thread.start()
        self.assertIn('idle_worker', wall_mode_output)
if __name__ == "__main__":
    unittest.main()
```

## Relevant State
- Initialization path: `_PyJit_TryInitializeTracing`
- Workload: threaded tracing initialization
- Leaked allocation: 72,000 bytes

## Leak Path
Tracing-initialization state outlives the test workload. The report does not
show whether it should be owned by an interpreter, thread, or JIT runtime.

## Fix
Trace the allocation's ownership from `_PyJit_TryInitializeTracing` and add
the matching teardown to the owner that survives initialization.
