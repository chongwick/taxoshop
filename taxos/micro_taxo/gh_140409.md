Hi @YuanchengJiang, we appreciate running fuzzers to catch bugs, but it's already very well known that you can cause crashes with `ctypes`. For example:

```py
import ctypes
ctypes.string_at(0)
```

Similarly, we don't care much about potential bugs/crashes in `_testcapi` or similar testing modules, because those aren't ever shipped to production code and solely exist for our test suite (in fact, we actually test for these crashes in some cases). For future fuzzing, please omit `ctypes` and other modules prefixed with `_`.
