# Micro Taxonomy: CPython #141336

## Metadata
- Issue: https://github.com/python/cpython/issues/141336
- Component: `Objects/unicodeobject.c`
- Bug class: assertion failure
- Detection: debug assertion

## Root Cause
A registered `unicode_escape` error handler returns replacement text and a
new input position while decoding an invalid escape. The decoder's writer
capacity accounting becomes inconsistent, violating its assertion that the
remaining source segment fits the remaining output space.

## Trigger
1. Register a custom `unicode_escape` error handler.
2. Decode malformed escape bytes using that handler.
3. The handler returns replacement text and a restart position.
4. Decoder output accounting reaches the writer-size assertion.

## Reproducer

```python
import codecs

decode = codecs.unicode_escape_decode
data = {b'\\x0': (b'\xe2\x98\x83', 0)}

def mutating(exc):
    key = exc.object[:exc.end]
    r = data.get(key)
    if r is not None:
        return ('Є', r[1])

codecs.register_error('test.mutating2', mutating)

input_obj = b'\\x0n\\z'
result, length = decode(input_obj, 'test.mutating2')
```


## Relevant State
- Decoder: `_PyUnicode_DecodeUnicodeEscapeInternal2`
- Callback: registered codec error handler
- Mutable state: source position and unicode writer capacity

## Re-entrancy Boundary
- Codec error-handler callback

## Failure Site
- `Objects/unicodeobject.c:6687`
- `end - s <= writer.size - writer.pos`

## Fix
Recompute or conservatively grow writer capacity after an error handler
changes the decode position; validate callback-provided restart positions.
