### Original Issue

Source: [https://github.com/python/cpython/issues/116886](https://github.com/python/cpython/issues/116886)

````text
PR authors and core devs have been seeing CIFuzz failures on PRs not related to their changes of late.  These are non-blocking, but confusing.

The CIFuzz build step is failing, it seems that _freeze_module crashes:

```
./Programs/_freeze_module importlib._bootstrap_external ./Lib/importlib/_bootstrap_external.py Python/frozen_modules/importlib._bootstrap_external.h
Segmentation fault (core dumped)
```

I believe _freeze_module got compiled with memory-sanitizer but no useful MSAN report seems to be generated by that crash.

Unclear where the problem lies, maybe this could be CIFuzz container or clang related?

CIFuzz background: read PR #107653 (discussion and links) and Issue #107652 (the pitch).

### CPython versions tested on:

CPython main branch

### Operating systems tested on:

Linux
````

```text
Another thought - the issue could be with the CI action itself. The CIFuzz job uses the `master` branch of the actions, so CPython's CI results are going to be dependent on the stability of the upstream repo. 

As an experiment, I modified the CIFuzz checkout on an older version of the action, and [ran it on a copy of #116454](https://github.com/freakboy3742/cpython/pull/4). 

If I revert to the 10e6cbd7 commit to oss-fuzz from a couple of days ago, the [CIFuzz test fails because of a clang issue failing to compile the code](https://github.com/freakboy3742/cpython/actions/runs/8304625844/job/22730491004), which is at least a *different* failure, and demonstrates that there's at least *some* sensitivity to the oss-fuzz version.
```
