### What happened?

`OrderedDict.copy()` iterates its nodes and calls `__getitem__` to fetch values. A re-entrant `__getitem__` that calls `clear()` during iteration frees all `_ODictNode` structures while `_odict_FOREACH` continues accessing them, resulting in a heap-use-after-free in `OrderedDict_copy_impl`.

**Proof of Concept:**
```python
from collections import OrderedDict

class Evil(OrderedDict):
    def __getitem__(self, key):
        super().clear()
        return None

# Trigger
Evil([(i, i) for i in range(4)]).copy()
```

### Comment 1 — superboy-zjc, 2025-12-16T10:00:21Z

Source: [https://github.com/python/cpython/issues/142734#issuecomment-3659727468](https://github.com/python/cpython/issues/142734#issuecomment-3659727468)

```text
The `OrderedDict.copy()` subclass branch iterates over `_ODictNode` pointers while calling `PyObject_GetItem()`. Since `PyObject_GetItem()` invokes the overridden `__getitem__`, it is possible for a re-entrant call to `clear()` frees all `_ODictNode` structs. The loop then continues and dereferences the freed node (via `_odictnode_KEY(node)`), resulting in a UAF.

A straightforward fix is to snapshot the keys (e.g., into a list) before any call to `PyObject_GetItem()`/Python. This avoids accessing raw node pointers during the iteration where re-entrancy is possible, and ensures keys remain alive even if clear() is invoked.
```
