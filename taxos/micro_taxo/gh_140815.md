### Comment 3 — sergey-miryanov, 2025-11-01T21:08:26Z

Source: [https://github.com/python/cpython/issues/140815#issuecomment-3476846830](https://github.com/python/cpython/issues/140815#issuecomment-3476846830)

```text
This segfault occurs because the `faulthandler_thread` runs concurrently with interpreter finalization. 

This happens because the `timeout` value of the `dump_traceback_later` is `10 * 1e-308` which is cropped to 1us. Therefore, the `faulthandler_thread` runs as soon as possible. 

`faulthandler_thread` doesn't use any synchronization primitives, so it is not a thread-safe, even in the GIL-enabled build.

I found an issue https://github.com/python/cpython/issues/128400 and a PR https://github.com/python/cpython/pull/128422 where the call to the `StopTheWorld` function was added to the `faulthandler_dump_traceback_py_impl` to prevent multithreading issues in the no-GIL build. Therefore, I believe this approach is valid for this issue as well. For the GIL-enabled build, I added the GIL acquisition.
```

### Comment 4 — vstinner, 2025-11-02T18:22:27Z

Source: [https://github.com/python/cpython/issues/140815#issuecomment-3478164228](https://github.com/python/cpython/issues/140815#issuecomment-3478164228)

```text
@sergey-miryanov:
> This segfault occurs because the faulthandler_thread runs concurrently with interpreter finalization.

`_Py_DumpTracebackThreads()` is called by the `faulthandler.dump_traceback_later()` thread while the main thread is freeing its frame.

`_Py_DumpTracebackThreads()` reads freed memory and does crash randomly. It already calls `_PyMem_IsPtrFreed()` in a few places to detect freed memory, but it's not enough.

> faulthandler_thread doesn't use any synchronization primitives, so it is not a thread-safe, even in the GIL-enabled build.

This is by design. `faulthandler.dump_traceback_later(exit=True)` dumps the traceback and exits the process to implement a software watchdog. It is used by buildbots and other CIs to exit after a timeout.

`faulthandler.dump_traceback_later()` should not attempt to acquire the GIL or any other lock since it's used to dump the traceback in case in other deadlocks.
```
